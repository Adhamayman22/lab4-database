Lab 3 - Problem 1 - Answers (COMPANY database)
===============================================

Database built with problem1_DDL.sql and filled with problem1_DML.sql.
Every block below was run with the MySQL client (MySQL 8.0):

    mysql -u root -p -t -vvv --force company < file.sql

so each statement is followed by the exact output or error that MySQL printed
("at line N" is the line of the statement inside that file).


-------------------------------------------------------------------------------
Q1.1  Insert a row in the DEPARTMENT table that references a row in the
      EMPLOYEE table. Then try to delete the referenced row. What will happen?
-------------------------------------------------------------------------------

SQL used:

    USE company;

    -- a new employee
    INSERT INTO employee (ssn, fname, lname, bdate, address, gender, salary, Dno)
    VALUES ('789123456', 'Hany', 'Fathy', '1983-04-04', '3 Roushdy St, Alexandria', 'M', 30000.00, 1);

    -- a new department that references him as its manager
    INSERT INTO department (Dnumber, Dname, mgr_ssn, mgr_start_date)
    VALUES (4, 'Marketing', '789123456', '2024-02-01');

    -- try to delete the referenced employee
    DELETE FROM employee WHERE ssn = '789123456';

    -- is he still there?
    SELECT ssn, fname, lname FROM employee WHERE ssn = '789123456';

Output:

    INSERT INTO employee ...
    Query OK, 1 row affected (0.00 sec)

    INSERT INTO department ...
    Query OK, 1 row affected (0.00 sec)

    DELETE FROM employee WHERE ssn = '789123456'
    ERROR 1451 (23000) at line 4: Cannot delete or update a parent row: a foreign
    key constraint fails (`company`.`department`, CONSTRAINT `department_ibfk_1`
    FOREIGN KEY (`mgr_ssn`) REFERENCES `employee` (`ssn`))

    SELECT ssn, fname, lname FROM employee WHERE ssn = '789123456'
    +-----------+-------+-------+
    | ssn       | fname | lname |
    +-----------+-------+-------+
    | 789123456 | Hany  | Fathy |
    +-----------+-------+-------+
    1 row in set (0.00 sec)

Answer:
    MySQL refuses the DELETE with error 1451 and the employee row stays in the
    table. Deleting him would leave department 4 with a mgr_ssn that points at
    nobody, which breaks referential integrity. The foreign key was created
    with the default action (RESTRICT / NO ACTION), so the parent row cannot be
    deleted while a child row still references it.

    To delete him we must first remove (or change) the row that references him:

    DELETE FROM department WHERE Dnumber = 4;
    Query OK, 1 row affected (0.00 sec)

    DELETE FROM employee WHERE ssn = '789123456';
    Query OK, 1 row affected (0.00 sec)


-------------------------------------------------------------------------------
Q1.2  Insert a row in the PROJECT table that references a row in the
      DEPARTMENT table that doesn't exist yet. What will happen?
-------------------------------------------------------------------------------

SQL used:

    USE company;

    -- department 9 does not exist
    INSERT INTO project (Pnumber, Pname, Plocation, Dno)
    VALUES (50, 'ProductZ', 'Alexandria', 9);

    SELECT Pnumber, Pname FROM project WHERE Pnumber = 50;

Output:

    INSERT INTO project (Pnumber, Pname, Plocation, Dno) VALUES (50, 'ProductZ', 'Alexandria', 9)
    ERROR 1452 (23000) at line 2: Cannot add or update a child row: a foreign
    key constraint fails (`company`.`project`, CONSTRAINT `project_ibfk_1`
    FOREIGN KEY (`Dno`) REFERENCES `department` (`Dnumber`))

    SELECT Pnumber, Pname FROM project WHERE Pnumber = 50
    Empty set (0.00 sec)

Answer:
    MySQL rejects the INSERT with error 1452 and no row is added. A foreign key
    value must be NULL or equal to a primary key value that already exists in
    the referenced table (referential integrity), and there is no department 9.

    It works once the department exists (parent first, then child):

    INSERT INTO department (Dnumber, Dname, mgr_ssn, mgr_start_date)
    VALUES (9, 'Sales', '456789123', '2025-01-01');
    Query OK, 1 row affected (0.00 sec)

    INSERT INTO project (Pnumber, Pname, Plocation, Dno)
    VALUES (50, 'ProductZ', 'Alexandria', 9);
    Query OK, 1 row affected (0.00 sec)

    (Both rows were deleted again afterwards so the seed data stays the same.)


-------------------------------------------------------------------------------
Q1.3  If mgr_ssn and Dno are both NOT NULL, how will you insert the first row
      in EMPLOYEE or DEPARTMENT?
-------------------------------------------------------------------------------

The problem
    EMPLOYEE.Dno -> DEPARTMENT and DEPARTMENT.mgr_ssn -> EMPLOYEE form a cycle.
    With both columns NOT NULL, the first employee needs an existing department
    and the first department needs an existing employee, and NULL is not
    allowed to "wait". We tried it on a copy of the schema (database
    company_q13) where both columns are NOT NULL and both foreign keys exist:

SQL used:

    CREATE DATABASE company_q13;
    USE company_q13;
    CREATE TABLE employee (ssn CHAR(9) NOT NULL, fname VARCHAR(30) NOT NULL,
        lname VARCHAR(30) NOT NULL, bdate DATE, address VARCHAR(100),
        gender CHAR(1), salary DECIMAL(10,2), Dno INT NOT NULL,
        PRIMARY KEY (ssn));
    CREATE TABLE department (Dnumber INT NOT NULL, Dname VARCHAR(30) NOT NULL,
        mgr_ssn CHAR(9) NOT NULL, mgr_start_date DATE, PRIMARY KEY (Dnumber),
        FOREIGN KEY (mgr_ssn) REFERENCES employee (ssn));
    ALTER TABLE employee ADD FOREIGN KEY (Dno) REFERENCES department (Dnumber);

    INSERT INTO employee (ssn, fname, lname, Dno) VALUES ('123456789', 'Ahmed', 'Hassan', 1);
    INSERT INTO department (Dnumber, Dname, mgr_ssn) VALUES (1, 'Research', '123456789');
    INSERT INTO employee (ssn, fname, lname, Dno) VALUES ('123456789', 'Ahmed', 'Hassan', NULL);

Output:

    INSERT INTO employee (ssn, fname, lname, Dno) VALUES ('123456789', 'Ahmed', 'Hassan', 1)
    ERROR 1452 (23000) at line 7: Cannot add or update a child row: a foreign
    key constraint fails (`company_q13`.`employee`, CONSTRAINT `employee_ibfk_1`
    FOREIGN KEY (`Dno`) REFERENCES `department` (`Dnumber`))

    INSERT INTO department (Dnumber, Dname, mgr_ssn) VALUES (1, 'Research', '123456789')
    ERROR 1452 (23000) at line 8: Cannot add or update a child row: a foreign
    key constraint fails (`company_q13`.`department`, CONSTRAINT
    `department_ibfk_1` FOREIGN KEY (`mgr_ssn`) REFERENCES `employee` (`ssn`))

    INSERT INTO employee (ssn, fname, lname, Dno) VALUES ('123456789', 'Ahmed', 'Hassan', NULL)
    ERROR 1048 (23000) at line 9: Column 'Dno' cannot be null

    So no order works: each table waits for the other.

Solution 1 (the one we use): insert the first rows BEFORE the foreign key that
closes the cycle exists, then add it with ALTER TABLE.
    Create EMPLOYEE without its foreign key, create DEPARTMENT (with its key to
    EMPLOYEE), insert the first employee (no check on Dno yet), insert the
    first department (the employee exists now), and only then add the foreign
    key of EMPLOYEE. ALTER TABLE checks the rows that are already there, so it
    only succeeds because the data is consistent.

SQL used:

    DROP DATABASE IF EXISTS company_q13;
    CREATE DATABASE company_q13;
    USE company_q13;
    CREATE TABLE employee ( ...same columns..., Dno INT NOT NULL, PRIMARY KEY (ssn));
    CREATE TABLE department ( ...same columns..., mgr_ssn CHAR(9) NOT NULL, ...,
        FOREIGN KEY (mgr_ssn) REFERENCES employee (ssn));

    INSERT INTO employee (ssn, fname, lname, Dno) VALUES ('123456789', 'Ahmed', 'Hassan', 1);
    INSERT INTO department (Dnumber, Dname, mgr_ssn) VALUES (1, 'Research', '123456789');
    ALTER TABLE employee ADD FOREIGN KEY (Dno) REFERENCES department (Dnumber);

    -- from now on the rule is enforced as usual
    INSERT INTO employee (ssn, fname, lname, Dno) VALUES ('234567891', 'Mona', 'Ali', 1);
    INSERT INTO employee (ssn, fname, lname, Dno) VALUES ('345678912', 'Omar', 'Khaled', 7);
    SELECT ssn, fname, Dno FROM employee;
    SELECT Dnumber, Dname, mgr_ssn FROM department;

Output:

    INSERT INTO employee ... ('123456789', 'Ahmed', 'Hassan', 1)
    Query OK, 1 row affected (0.00 sec)

    INSERT INTO department ... (1, 'Research', '123456789')
    Query OK, 1 row affected (0.00 sec)

    ALTER TABLE employee ADD FOREIGN KEY (Dno) REFERENCES department (Dnumber)
    Query OK, 1 row affected (0.02 sec)
    Records: 1  Duplicates: 0  Warnings: 0

    INSERT INTO employee ... ('234567891', 'Mona', 'Ali', 1)
    Query OK, 1 row affected (0.00 sec)

    INSERT INTO employee ... ('345678912', 'Omar', 'Khaled', 7)
    ERROR 1452 (23000) at line 10: Cannot add or update a child row: a foreign
    key constraint fails (`company_q13`.`employee`, CONSTRAINT `employee_ibfk_1`
    FOREIGN KEY (`Dno`) REFERENCES `department` (`Dnumber`))

    +-----------+-------+-----+
    | ssn       | fname | Dno |
    +-----------+-------+-----+
    | 123456789 | Ahmed |   1 |
    | 234567891 | Mona  |   1 |
    +-----------+-------+-----+
    2 rows in set (0.00 sec)

    +---------+----------+-----------+
    | Dnumber | Dname    | mgr_ssn   |
    +---------+----------+-----------+
    |       1 | Research | 123456789 |
    +---------+----------+-----------+
    1 row in set (0.00 sec)

Solution 2: switch the foreign-key checks off for the session while inserting
the pair of rows that point at each other, then switch them on again.
    MySQL does not check the keys while FOREIGN_KEY_CHECKS = 0 (and does not
    re-check old rows when it is set back to 1), so we must make sure the rows
    are correct ourselves.

SQL used (same database, both foreign keys already in place):

    SET FOREIGN_KEY_CHECKS = 0;
    INSERT INTO employee (ssn, fname, lname, Dno) VALUES ('456789123', 'Sara', 'Mahmoud', 2);
    INSERT INTO department (Dnumber, Dname, mgr_ssn) VALUES (2, 'Administration', '456789123');
    SET FOREIGN_KEY_CHECKS = 1;
    SELECT ssn, fname, Dno FROM employee;
    SELECT Dnumber, Dname, mgr_ssn FROM department;

Output:

    SET FOREIGN_KEY_CHECKS = 0
    Query OK, 0 rows affected (0.00 sec)

    INSERT INTO employee ... ('456789123', 'Sara', 'Mahmoud', 2)
    Query OK, 1 row affected (0.00 sec)

    INSERT INTO department ... (2, 'Administration', '456789123')
    Query OK, 1 row affected (0.00 sec)

    SET FOREIGN_KEY_CHECKS = 1
    Query OK, 0 rows affected (0.00 sec)

    +-----------+-------+-----+
    | ssn       | fname | Dno |
    +-----------+-------+-----+
    | 123456789 | Ahmed |   1 |
    | 234567891 | Mona  |   1 |
    | 456789123 | Sara  |   2 |
    +-----------+-------+-----+
    3 rows in set (0.00 sec)

    +---------+----------------+-----------+
    | Dnumber | Dname          | mgr_ssn   |
    +---------+----------------+-----------+
    |       1 | Research       | 123456789 |
    |       2 | Administration | 456789123 |
    +---------+----------------+-----------+
    2 rows in set (0.00 sec)

    DROP DATABASE company_q13;
    Query OK, 2 rows affected (0.01 sec)

Answer:
    With both columns NOT NULL the two tables wait for each other, so the first
    row cannot be inserted in the normal way: every order fails (errors 1452
    and 1048 above). A transaction does not help in MySQL, because InnoDB checks
    a foreign key immediately after each statement (it has no deferred
    constraints). We can:
      1. insert the first employee and the first department before the foreign
         key that closes the cycle exists, and add it afterwards with
         ALTER TABLE ... ADD FOREIGN KEY (MySQL checks the existing rows when
         the key is added); or
      2. turn the checks off for a moment with SET FOREIGN_KEY_CHECKS = 0,
         insert the two rows, and turn them on again with
         SET FOREIGN_KEY_CHECKS = 1.
    This is also why our own DDL keeps mgr_ssn and Dno nullable: the DML inserts
    the employees with Dno = NULL first, then the departments, then sets Dno
    with UPDATE.
